# Daily Blog Writing Workflow (네이버 · 티스토리 통합 일일 워크플로우)

## 1. 목적

AI를 활용하여 **네이버 블로그**와 **티스토리** 콘텐츠를 효율적으로 기획·작성·검증·발행한다.

- **네이버 블로그**: 실시간 이슈와 국내 독자의 관심 검색어 중심 (하루 3~5편, 스마트블록 및 이웃 소통 유입)
- **티스토리**: 구체적인 검색 질문, 문제 해결, 장기 검색 유입 중심 (하루 1편 / 주 5편, 구글 검색 SEO 및 애드센스 수익)
- **공통 원칙**: 정확성, 독창성, 출처 검증, 지속 가능한 운영 (`주제 조사 한 번 → 플랫폼별 맞춤 글 분리 작성`)

---

## 2. 매일 작업 순서 (8단계 표준 절차)

### Step 1. 주제 수집
- 네이버 실시간 검색어 TOP 10 및 주요 국내 이슈 확인
- [Google Trends](https://trends.google.com/trends/?geo=KR) 상승 검색어 및 관련 검색어 확인
- 기존 주제 목록(`topics/topic-backlog.md`, `logs/publishing-log.csv`)과 중복 여부 확인
- 오늘의 후보 주제 5~10개 기록

### Step 2. 주제 평가 (100점 만점 루브릭)
각 후보를 다음 5가지 기준으로 **1~5점** 평가한다 (합산 × 4 = 100점 만점).

| 평가 항목 | 배점 (1~5점) | 핵심 판단 질문 |
| :--- | :---: | :--- |
| **1. 검색 관심도** | 1 ~ 5점 | Google Trends 및 포털에서 최근 검색 관심도가 상승하고 있는가? |
| **2. 검색 의도의 명확성** | 1 ~ 5점 | 독자가 해결하려는 구체적인 질문(방법·비교·가격·조건)이 명확한가? |
| **3. 경쟁 콘텐츠의 빈틈** | 1 ~ 5점 | 기존 상위 글에 최신 공식 표, 단계별 절차, 주의사항이 부족한가? |
| **4. 자료 확인 가능성과 작성 역량** | 1 ~ 5점 | 공식 기관·제조사 자료와 나의 경험/지식으로 정확히 검증해 쓸 수 있는가? |
| **5. 장기 검색 가능성** | 1 ~ 5점 | 유행이 지나도 몇 주~몇 달 뒤까지 꾸준히 검색될 주제인가? |

- 점수가 높은 주제(70점 이상)를 우선 검토하되, 검색 수요가 불확실하거나 사실 확인이 어려운 주제는 제외한다.

### Step 3. 플랫폼별 주제 결정
- **네이버**: 시의성, 국내 관심도, 빠른 정보 전달과 공감(5060 품미인생 관점)을 고려한다.
- **티스토리**: 검색 질문에 대한 구체적인 답(단계별 절차, 조건별 비교표)과 지속성을 고려한다.
- 동일한 주제를 사용할 경우 **제목과 구성, 독자에게 제공하는 가치를 완전히 차별화**한다 (단순 복사·붙여넣기 금지).

### Step 4. 자료 조사
- 공식 기관(국민연금공단, 건보공단, 한국은행, 한국거래소 등), 제조사, 서비스 제공자의 자료를 우선 확인한다.
- 숫자, 날짜, 가격, 세율, 정책 및 제품 사양을 검증한다.
- 출처 URL과 확인 날짜를 기록한다 (`guidelines/source-policy.md` 준수).
- 확인하지 못한 사실은 확정적으로 서술하지 않고 `[확인 필요]`로 표시하거나 개인별 조건 차이를 안내한다.

### Step 5. AI 초안 작성
- 독자가 검색하는 질문에 대한 **핵심 답변을 도입부에서 먼저 제시**한다.
- 제목과 소제목(H2/H3)을 구체적으로 작성한다.
- 필요에 따라 **단계별 설명(1단계~4단계), 비교표(Table), 사례 및 주의사항**을 포함한다.
- 실제로 수행하지 않은 경험을 개인 경험처럼 작성하지 않는다.
- 다른 글을 단순 복사하거나 문장만 바꾼 콘텐츠를 만들지 않는다.

### Step 6. 품질 검증 (`prompts/fact-check.md` 기준)
- [ ] 사실과 수치가 공식 출처에 부합하는가?
- [ ] 제목이 본문에서 실제로 답하는 내용과 일치하는가?
- [ ] 반복 문장과 불필요한 상투적 서론이 없는가?
- [ ] 이미지와 인용 자료의 사용 권리가 적절한가?
- [ ] 개인정보, 저작권, 광고 표시 등 관련 정책을 준수하는가?
- [ ] 독자가 이 글만 읽고도 실제로 문제를 해결할 수 있는가?

### Step 7. 발행 (`workflow/publishing.md` 기준)
- 카테고리와 최종 제목 확인
- 외부 공식 링크와 이미지 정상 노출 확인
- PC 및 모바일 화면 미리보기 점검 (특히 표 깨짐 여부 확인)
- 공개 설정 및 검색 허용 확인
- 게시글 URL과 발행일을 `logs/publishing-log.csv`에 기록

> ⚠️ 자동 초안 생성 배치를 운영하더라도 **최종 사실 검증 및 실제 블로그 발행 승인 단계**는 운영자가 직접 확인한다.

### Step 8. 성과 기록
`logs/publishing-log.csv`에 아래 항목을 기록하고 추적한다.
- 발행일 (`date`)
- 플랫폼 (`platform`: Naver / Tistory)
- 카테고리 (`category`)
- 주제 및 제목 (`topic`, `title`)
- 게시글 URL (`url`)
- 상태 (`status`: draft / published)
- 검색 노출(`impressions`) 및 클릭(`clicks`)
- 방문자 수(`visitors`)
- 광고 수익(`revenue`: 확인 가능한 경우)
- 개선할 점(`notes`)

## 3. 매일 작업 시간 배분 (30분 표준 루틴)

| 단계 | 작업 내용 | 권장 소요 시간 |
| :--- | :--- | :---: |
| **1. 주제 수집 및 선정** | 실시간 검색어 Top 10 & Google Trends 상승 검색어 확인, 100점 평가 | **5분** |
| **2. 자료 확인** | 공식 기관·제조사 페이지에서 핵심 수치·조건·URL 확인 | **5분** |
| **3. AI 초안 작성** | 플랫폼별 맞춤 프롬프트(`naver-draft.md`, `tistory-draft.md`)로 초안 생성 | **10분** |
| **4. 검증 및 편집** | 숫자·연도 대조, 가상 경험 문장 제거, 비교표 및 출처 링크 점검 | **7분** |
| **5. 발행 및 기록** | 에디터 서식 복사 후 발행, `logs/publishing-log.csv`에 URL 기록 | **3분** |
| **합계** | **일일 표준 작업 시간** | **총 30분** |

---

## 4. 주간 리뷰 (`workflow/performance-review.md` 연계)

매주 일요일(또는 주 1회) 다음 5가지를 확인하여 `logs/weekly-review.md`에 기록한다.
1. 어떤 주제와 카테고리에서 검색 노출과 클릭이 발생했는가?
2. 제목과 본문 도입부 중 클릭률(CTR)과 체류 시간을 높이기 위해 개선할 부분은 무엇인가?
3. 이슈가 지난 뒤에도 지속적으로 검색 유입이 발생하는 효자 글은 무엇인가?
4. 다음 주에 후속편이나 연재로 확장할 주제는 무엇인가?
5. 근거가 부족하거나 성과가 낮은 글을 어떻게 보완할 것인가? *(주의: 성과가 낮다는 이유만으로 글을 성급하게 삭제하지 않고, 충분한 색인·관찰 기간을 거친 뒤 제목·본문 보완 여부를 결정한다.)*

## 5. 매일 AI 에이전트(Claude Code / Gemini / Antigravity)에 입력할 실행 명령

```markdown
이 저장소의 README.md와 workflow/daily-workflow.md를 먼저 읽어 주세요.

오늘의 블로그 콘텐츠 작업을 시작합니다.

1. topics/topic-backlog.md와 logs/publishing-log.csv에서 기존 주제와 중복되는 항목을 확인합니다.
2. 네이버 블로그용 실시간 이슈 주제 후보와 티스토리용 검색형 주제 후보를 구분합니다.
3. 실제 최신 검색 데이터를 확인할 수 없는 경우 검색량이나 순위를 추측하지 말고, 추가 조사가 필요한 항목으로 표시합니다.
4. 후보별 검색 의도, 장기성, 경쟁 콘텐츠의 빈틈, 사실 확인 가능성을 1~5점으로 평가합니다.
5. 우선 작성할 주제를 추천하고, 선정 이유와 필요한 공식 출처를 제시합니다.
6. 승인된 주제에 대해서만 해당 플랫폼의 작성 지침(guidelines/naver-blog.md, guidelines/tistory-seo.md)에 따라 초안을 생성합니다.
7. prompts/fact-check.md와 workflow/publishing.md 기준으로 검토하고, 미확인 사실과 발행 전 점검 항목을 별도로 출력합니다.
```
